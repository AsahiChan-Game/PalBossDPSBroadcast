# 测试说明

## 运行方式

需要 Node.js/npm。在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tests\run_all.ps1
```

脚本使用临时 `npx` 包解析并运行 Lua，不访问 PalServer 进程或在线服务器文件。

## 自动检查范围

- `main.lua`、`config.lua` 和 `commentary.lua` 语法解析。
- 所有 Lua 文件严格 UTF-8 验证。
- 已知危险旧 API 静态审计。
- 原生伤害/死亡/捕捉钩子不访问 UObject。
- 临时事件参数生命周期与失效 Actor 处理。
- 捕捉、击杀、超时和重复结束幂等性。
- 中央 `PalCaptureSuccess` 的玩家/Boss 参数顺序。
- 多 Boss 会话隔离。
- 月亮领主多部位合并、非主体死亡不提前结算以及并行复合遭遇隔离。
- 玩家角色、普通帕鲁和坐骑技能归属。
- 长中文帕鲁昵称与本地化名称。
- 收件人 `TArray<FGuid>` 单次调用、参与者隔离和旁观者零消息。
- 默认精简模式严格行数与 MVP 排名。
- 实时战况、详细奖项、队内明细和趣味点评的独立开关。
- 同公会个人明细隔离、个人/公会占比分母、新开关优先级及旧配置兼容。
- 明细行数截断保留总伤害；本机身份无法识别时不向远程参与者泄漏明细。
- `EnableDPSRecording=false` 时不接收事件、不创建会话、不发消息。
- 10,000 次伤害突发下的队列上限和结束事件保留。
- 1,000 次同源帕鲁多段命中的归属/玩家/名称缓存，以及普通目标快速负缓存。

## 实机灰度建议

离线测试不能替代 Palworld 的真实反射对象和网络复制。首次安装或游戏大版本更新后，建议在维护窗口依次验证：

1. 单人击杀一个普通野外 Boss。
2. 捕捉一个普通野外 Boss。
3. 两人攻击同一 Boss，确认双方各收到一次结算。
4. 让旁观者不造成伤害，确认其收不到战报。
5. 在石板或多 Boss 房间确认各 Boss 独立结算。

若发生异常，请保留 `UE4SS.log` 中从模组加载到战斗结束的相关行。
